# Business Quant 배당 전환 — 운영 배포 전 보고서

작성일: 2026-09-29. 이 문서는 로컬 구현·검증 결과이며 운영 배포 승인이 아니다.

1. **기존 DB 구조**: 회사·관심목록·가격·일봉·SEC 재무, 옛 Alpha 배당 원본/요약, Massive 배당 원본이 분리되어 있었다. 현재 로컬 D1의 Alpha 테이블은 제거했고 Massive 원본과 SEC 재무는 보존했다. 운영 D1은 변경하지 않았다.
2. **변경 파일**: `worker/src/index.js`, `worker/src/fundamental-sync.js`, `worker/src/massive-sync.js`, `app.js`, `fundamental-progress.js`, `index.html`, `worker/wrangler.jsonc`, `package.json`, `README.md` 및 관련 테스트. 새 파일은 `worker/src/businessquant-{metrics,sync,view}.js`, `scripts/businessquant-audit.mjs`, `tests/businessquant.test.js`다. 사용하지 않는 `worker/src/alpha-dividends.js`와 `worker/src/dividend-view.js`는 제거했다.
3. **D1 마이그레이션**: `0014_businessquant_dividends.sql`과 `0015_retire_alpha_dividends.sql`을 로컬 D1에 적용했다. 0015는 Alpha 배당 원본·요약·예산·속도제한 테이블과 구식 배당 작업 행을 삭제한다. 적용 전 로컬 Alpha 원본은 0건이었다. SEC 재무와 Massive 원본은 보존한다. 원격 D1에는 적용하지 않았다. 과거 0010~0013 파일은 기존 운영 DB와 새 DB의 순차 마이그레이션을 위해 보존한다.
4. **이력 테이블**: `bq_dividend_history`는 `(ticker,ex_date,source)` 기본 키에 지급일·주당액·최초/최근 확인 시각을 보관한다. 동일 배당락일에 서로 다른 두 이벤트가 오면 손실성 병합 대신 해당 응답을 거부하고 기존 저장본을 유지한다.
5. **요약 테이블**: `bq_dividend_summary`는 이력 범위, 지급액, 미래 확정된 공급원 이벤트, 완료 연도 성장률, 내부 추정일, 수집 시각/상태를 분리 저장한다. 현재가 의존 수익률은 요약 지급액과 기존 저장 가격을 읽을 때 계산한다.
6. **증분 동기화**: API에서 전체 이력이 와도 기존 `(ticker,ex_date)`와 비교해 신규 INSERT, 금액·지급일 정정 UPDATE만 수행한다. 동일 행은 쓰지 않고 API 누락을 DELETE로 해석하지 않는다.
7. **스마트 스케줄러**: 관심목록을 종목 진실 원본으로 삼는다. 새 Massive 선언, 신규 종목, 배당 임박, 오래된 동기화, 일반 갱신 순으로 한 번에 한 종목을 고른다. 내부 예상일로 1/3/7/30일 간격을 정하며 미처리 종목은 다음 Cron에 남는다. 종목 삭제 시 이력은 보존한다.
8. **하드 호출 한도**: `bq_api_requests`의 원자적 예약으로 UTC일 24회와 최근 24시간 24회를 동시에 제한한다. 같은 티커의 당일 중복도 차단한다. 401/403/429는 그 UTC일 자동 수집을 멈춘다. 운영 공급원의 실제 리셋 시간은 확인되지 않아 최근 24시간 제한도 적용했다.
9. **Massive 트리거**: 기존 `massive_dividend_events`는 새 원본과 다른 행만 UPSERT하며 응답 누락으로 삭제하지 않는다. 새 미래 선언을 감지하면 BQ 우선순위를 높인다. 관심종목별 Massive 확인은 1~3일 간격이며 15분마다 최대 한 종목을 검사한다. 이는 즉시 푸시가 아니라 최대 약 1~3일 탐지 지연이 있는 폴링이다.
10. **예상 배당락일**: 최근 정기 이벤트 6건 이상에서 여러 배당락일 간격의 중앙값을 사용한다. 내부 `next_bq_fetch_at`에만 활용하며 화면에는 표시하지 않는다.
11. **상세 카드 출처**: 빈도·지급액·실제 지급 수익률·마지막 지급·미래 배당락/금액/지급일·성장률·확보 이력 내 성장 연수는 BQ 저장본, 마지막 종류·미래 선언일은 Massive 저장본, 수익률 분모는 기존 저장 가격이다. 화면 요청에서 외부 API는 호출하지 않는다.
12. **성장률**: 마지막 완료 역년 DPS를 기준으로 1년 전년 대비, 5·10년 CAGR을 계산한다. 해당 연도 정기 배당을 배당락일 기준으로 합산한다. 비교 연도·이력이 부족하면 `null`이다.
13. **성장 연수**: 마지막 완료 역년부터 연속으로 `DPS_current > DPS_previous`인 횟수만 센다. 공급원 확보 범위를 넘는 공식 회사 성장연수로 표시하지 않는다.
14. **특별배당과 분할**: Massive가 `special`/`supplemental`로 확인한 날짜만 성장률에서 제외한다. 오래된 미분류 배당은 임의로 제외하지 않는다. BQ 응답에는 분할 조정 여부가 명시되지 않고 [공식 예시](https://businessquant.com/docs/api/dividends)에 분할 전후로 보이는 큰 DPS 단절이 있어, 급변 구간을 가로지르는 성장률·최근 1년 수익률은 `미확보`로 숨기고 경고한다. 완전한 분할 보정은 별도 신뢰 가능한 장기 split 이력이 확보되어야 한다.
15. **Alpha Vantage 작업**: 활성/비활성 Alpha 배당 수집·표시 코드를 제거했다. 상태 API의 Alpha Secret 플래그와 환경 예시, 로컬 `.dev.vars`의 Alpha 키 항목도 제거했다. 운영 Secret은 값 확인·삭제를 수행하지 않았으며, 운영 DB의 Alpha 테이블은 0015 적용 전까지 남는다. 이 작업은 회사·SEC 재무·Massive·일봉 공급원을 변경하지 않는다.
16. **6종목 실자료 dry-run**: 새 로컬 키로 6종목 모두 HTTP 200을 받았다. 읽기 전용 `scripts/businessquant-audit.mjs`에서 실제 원본 전체 이력을 파싱하고 저장된 로컬 Massive 원본과 교차했다. O는 월, 나머지 5종목은 분기배당으로 판별했다. 미래 배당락·금액·지급일은 JPM/O/ABBV/ABT에 있었고 PG/JNJ에는 없었다. 상세 결과는 아래 표에 있다. 로컬 가격 테이블에는 이 종목들의 저장 가격이 없어 실자료의 `paid yield 1Y`는 계산하지 못했다. Massive 로컬 원본은 O/ABT에만 있어 나머지 네 종목의 종류·선언일은 로컬에서 확인하지 못했다.
17. **신규/변경/동일 수**: 실자료 6종목 전체 700건에 대한 로컬 DB 읽기 전용 비교 결과 `existing=0, inserted=700, updated=0, unchanged=0`이었다. 이는 **예상 INSERT 수**이지 실제 저장 수가 아니다. SQLite 통합 테스트에서는 275건 최초 INSERT → 동일 재수집 0건 쓰기 → 신규 1건 INSERT → 정정 1건 UPDATE → API에서 과거 1건 누락돼도 DB 276건 유지가 확인됐다.
18. **테스트**: `npm run check`와 `npm test` 통과(68/68). 로컬 D1 마이그레이션 성공, Alpha 테이블 제거와 BQ/Massive/SEC 재무 보존을 별도 회귀 테스트로 확인했다. 운영 Worker·Pages와 원격 D1은 건드리지 않았다. PIN/브라우저 수동 조작은 이번 로컬 단계에서 별도 확인하지 못했다.

## 승인 전 남은 확인

- 실제 BQ 원본의 분할 조정 정책과 필요한 장기 split 자료를 확인한다. 확인되지 않은 급변 구간의 성장률은 계속 숨긴다.
- 운영 승인 후에만 원격 마이그레이션·Cron을 설정한다. 운영 Secret은 사용자가 등록했다고 알렸으나 CLI 인증이 없어 이름을 직접 확인하지는 못했다. 첫 활성화는 `DIVIDEND_SYNC_TICKERS=O,JPM,ABT`와 `DIVIDEND_PIPELINE_ENABLED=true`를 사용해 최대 3종목으로 제한하고, 저장·화면·호출 카운터를 검증한 뒤 전체 종목으로 넓힌다.
- Alpha Vantage 운영 Secret은 별도 인증된 Cloudflare 관리 경로에서 삭제해야 한다. 이번 로컬 변경은 운영 Secret을 건드리지 않았다.
- 노출된 API 키는 공급원에서 폐기·재발급하고 새 키는 채팅에 올리지 않는다.

## 2026-09-29 후속 수정: 배당주기별 성장률

위 표는 당시 배당락일 연도 합산 방식의 기록이며, 성장률 수치는 최신 계산 방식의 결과가 아니다. 이후 O의 2024년 배당락 11건·2025년 13건으로 1년 성장률이 22.03%로 부풀려지는 문제가 확인됐다.

- 최근 정기 배당락일 간격으로 월·분기·반기·연 주기를 판별하고, 성장률은 **완료된 지급연도**의 정기 배당금 합계로 계산한다.
- 비교 구간의 각 연도에 월 12회·분기 4회·반기 2회·연 1회가 모두 있어야 1년 YoY와 5·10년 CAGR을 표시한다. 주기 미확인·누락·추가 지급은 임의 보정하지 않는다.
- 기존 요약은 외부 API 재호출 없이 저장된 이력에서 일별 갱신 시 다시 계산한다. 운영 배포 전까지 운영 화면 수치는 바뀌지 않는다.
- Business Quant 주당배당금의 소수점 정밀도가 실제 회사 공시보다 낮을 수 있으므로, 지급 횟수를 바로잡아도 회사 공식 연간 DPS와 차이가 남을 수 있다.
